# Задача 1. Максимум и минимум

## Обозначения и модель расчёта

`n` — количество элементов массива, `1 < n < 100000`.
Операции с `int`, сравнение, присваивание и обращение по индексу считаются операциями постоянного времени. Чтение одного числа фиксированного диапазона также учитывается как O(1). Оценивается алгоритм программы без фиксированных расходов JVM; время ожидания ввода пользователем не учитывается.

## Идея решения

Программа считывает массив. Начальные минимум и максимум равны первому элементу. Затем каждый элемент сравнивается с текущими экстремумами. Если найдено большее или меньшее значение, соответствующая переменная обновляется.

## Временная сложность

1. Создание и инициализация массива — O(n).
2. Чтение элементов — n итераций, O(n).
3. Присваивание `max = arr[0]` и `min = arr[0]` — O(1).
4. Поиск экстремумов — n итераций. В каждой выполняется одно или два сравнения значений и не более одного обновления экстремума: O(1) на итерацию, O(n) на цикл.
5. Вывод двух чисел — O(1).

Циклы выполняются последовательно, поэтому их сложности складываются:

T(n) = O(n) + O(n) + O(1) + O(n) + O(1) = O(n).

В лучшем, среднем и худшем случаях программа проходит весь массив, поэтому точный порядок роста — Θ(n).

Первый элемент уже учтён при инициализации. Поисковый цикл можно начать с `i = 1`, сократив его до n − 1 итераций. Асимптотика останется Θ(n).

## Пространственная сложность

Массив содержит n элементов типа int: 4n байт полезных данных плюс служебные расходы объекта. Общая память программы под данные — O(n).

Переменные `n`, `i`, `min`, `max` занимают постоянный объём. Дополнительная память поиска без учёта исходного массива — O(1).

## Итог

- Время всей программы: O(n), точнее Θ(n).
- Общая память под данные: O(n).
- Дополнительная память поиска: O(1).
