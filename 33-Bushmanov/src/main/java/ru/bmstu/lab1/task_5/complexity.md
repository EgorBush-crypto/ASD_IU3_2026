# Задача 5. Сумма элементов с чётными индексами

## Обозначения

`n` — количество элементов массива, `1 < n < 100000`.
Используется модель, в которой сравнение, присваивание, арифметическая операция над int или long и обращение к элементу массива занимают O(1). Чтение и вывод одного числа фиксированного диапазона учитываются как O(1). Время ожидания ввода человеком не учитывается. Фиксированные расходы JVM и ввода-вывода не меняют приведённые порядки роста.

O обозначает верхнюю асимптотическую оценку, Θ — точный порядок роста.

## Идея решения

Программа считывает массив из n целых чисел. Затем цикл с начальным индексом 0 и шагом 2 складывает элементы с индексами 0, 2, 4 и так далее. Чётность значений элементов не проверяется: условие относится именно к индексам.

Сумма хранится в long. Число складываемых элементов не превышает 50000, поэтому даже сумма крайних значений int по модулю не превышает 50000 × 2147483648 = 107374182400000. Это находится в диапазоне long.

## Расчёт времени

1. Создание и обнуление массива длины n — O(n).
2. Чтение массива — n итераций, Θ(n).
3. Инициализация суммы — O(1).
4. Цикл суммирования выполняет ceil(n / 2) итераций. Если n чётное, их n / 2; если нечётное — (n + 1) / 2. Каждая итерация содержит постоянное число действий, поэтому время — Θ(n).
5. Вывод суммы — O(1).

Циклы идут последовательно, поэтому их время складывается:

T(n) = O(n) + Θ(n) + Θ(ceil(n / 2)) + O(1) = Θ(n).

Для двух явных циклов суммарное число итераций равно n + ceil(n / 2). Множитель около 1,5 не меняет линейный порядок роста.

Досрочного выхода нет. Лучший, средний и худший случаи — Θ(n).

## Расчёт памяти

Исходный массив содержит n элементов int: 4n байт полезных данных плюс служебные расходы. Общая память под данные — O(n).

Переменные n, i и sum занимают постоянный объём. Второй массив не создаётся. Дополнительная память вычисления суммы без учёта исходного массива — O(1).

## Итог

- Время всей программы: O(n), точнее Θ(n).
- Общая память под данные: O(n).
- Дополнительная память суммирования: O(1).
