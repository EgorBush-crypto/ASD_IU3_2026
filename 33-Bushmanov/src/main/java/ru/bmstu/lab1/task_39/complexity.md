# Задача 39. Циклический сдвиг вправо

## Обозначения и модель

n — число элементов, 1 < n < 100000. Сравнение, присваивание, обращение по индексу и арифметика над int и long считаются операциями O(1). Чтение и вывод одного числа фиксированного диапазона учитываются как O(1). Ожидание ввода человеком и постоянные расходы JVM не учитываются. O — верхняя оценка, Θ — точный порядок роста.

## Идея решения и корректность

Для непустого массива вычисляется step = Math.floorMod(k, n). Полные обороты не меняют массив, поэтому достаточно сдвига на step позиций, где 0 ≤ step < n.

Элемент с индексом i записывается во временный массив на индекс (i + step) % n. Добавление step сдвигает вправо, а остаток от деления возвращает индекс в начало массива при переходе через правую границу. Разные исходные индексы получают разные новые позиции. Затем результат копируется в исходный массив.

При step = 0 метод заканчивается без создания временного массива. Проверка пустого массива выполняется раньше вычисления остатка и предотвращает деление на ноль. Пустой массив не требуется исходным ограничением, но метод его обрабатывает.

При n < 100000 сумма i + step меньше 200000, поэтому вычисление индекса в int не переполняется. Большое k не приводит к повторению сдвига k раз: вычисление остатка для int занимает O(1).

## Время метода changer

При step = 0 выполняется постоянное число операций: Θ(1).

При ненулевом step:

1. Проверки и вычисление step — O(1).
2. Создание и обнуление shift длины n — O(n).
3. Расстановка элементов — n итераций, Θ(n).
4. Копирование в исходный массив — n итераций, Θ(n).

T_changer(n) = O(n) + Θ(n) + Θ(n) = Θ(n).

Два последовательных цикла дают 2n итераций, а не n².

## Время всей программы

Чтение исходного массива требует Θ(n). Вывод результата также требует Θ(n), в том числе при нулевом сдвиге.

T(n) = Θ(n) + T_changer(n) + Θ(n) = Θ(n).

Следовательно, вся программа работает за Θ(n) и в лучшем, и в худшем случае. Досрочный возврат меняет время метода, но не порядок роста всей программы.

## Расчёт памяти

Исходный массив arr содержит n значений int и занимает O(n) памяти. При ненулевом step дополнительно создаётся shift из n значений int: ещё O(n). Оба массива вместе содержат 8n байт полезных данных плюс служебные расходы.

Общая память: O(n) + O(n) = O(n).
Дополнительная память метода при ненулевом step — O(n), при step = 0 — O(1), поскольку shift не создаётся. Параметр a ссылается на исходный массив, отдельной копией он не является.

## Итог

- Время всей программы: Θ(n) во всех случаях.
- Время changer: Θ(1) при нулевом нормализованном сдвиге, Θ(n) иначе.
- Общая память: O(n).
- Дополнительная память changer: O(n) в худшем случае, O(1) при нулевом сдвиге.
