# Задача 28. Медиана массива

## Обозначения и модель

n — число элементов, 1 < n < 100000. Сравнение, присваивание, обращение по индексу и арифметика над int и long считаются операциями O(1). Чтение и вывод одного числа фиксированного диапазона учитываются как O(1). Ожидание ввода человеком и постоянные расходы JVM не учитываются. O — верхняя оценка, Θ — точный порядок роста.

## Идея решения и корректность

Программа читает массив и сортирует его по неубыванию через Arrays.sort(int[]). При нечётной длине медиана находится по индексу n / 2. При чётной длине берётся среднее элементов с индексами n / 2 − 1 и n / 2.

В выражении ((long) arr[n / 2 - 1] + arr[n / 2]) / 2.0 преобразование в long выполняется до сложения и предотвращает переполнение int. Деление на 2.0 выполняется в double и сохраняет дробную часть. Все возможные медианы массивов из int точно представимы в double.

Метод median предполагает непустой, уже отсортированный массив. В main эти условия выполнены при корректном входе.

## Расчёт времени

1. Создание и заполнение массива — Θ(n).
2. Arrays.sort(int[]) — O(n log n) по описанию реализации Java SE 25.
3. Метод median — O(1): выполняет проверку чётности, одно или два обращения к массиву и постоянное число арифметических операций. Циклов в нём нет.
4. Вывод одного результата — O(1).

T(n) = O(n) + O(n log n) + O(1) = O(n log n).

Это верхняя оценка всей программы. Она не означает, что любой вход обязательно требует Θ(n log n): реализация OpenJDK 25 распознаёт монотонные последовательности, и на уже упорядоченном массиве возможен линейный проход. Лучшее время всей программы — Θ(n), худшее — Θ(n log n).

## Расчёт памяти

Исходный массив занимает O(n) памяти: 4n байт полезных данных плюс служебные расходы. Сам метод median использует O(1) дополнительной памяти.

Память библиотечной сортировки нужно учитывать отдельно. В реализации OpenJDK 25 класс DualPivotQuicksort может обнаруживать упорядоченные участки и сливать их. Для слияния в методе tryMergeRuns может выделяться вспомогательный массив int[size]. Поэтому дополнительная память сортировки в худшем случае — O(n); считать всю сортировку безусловно O(1) по дополнительной памяти неверно.

Оценка относится к рассмотренной реализации OpenJDK 25. Детали алгоритма являются особенностью реализации, а не универсальным требованием интерфейса Arrays для всех JDK.

Общая память программы: O(n) для входного массива + O(n) вспомогательной памяти в худшем случае = O(n).

## Итог

- Время всей программы: O(n log n); лучший случай Θ(n), худший Θ(n log n) для рассмотренной реализации.
- Время метода median после сортировки: O(1).
- Общая память: O(n).
- Дополнительная память с учётом сортировки: O(n) в худшем случае для OpenJDK 25.
- Дополнительная память только метода median: O(1).
