# Задача 15. Пузырьковая сортировка с подсчётом обменов

## Обозначения

`n` — количество элементов массива, `1 < n < 100000`.
Используется модель, в которой сравнение, присваивание, арифметическая операция над int или long и обращение к элементу массива занимают O(1). Чтение и вывод одного числа фиксированного диапазона учитываются как O(1). Время ожидания ввода человеком не учитывается. Фиксированные расходы JVM и ввода-вывода не меняют приведённые порядки роста.

O обозначает верхнюю асимптотическую оценку, Θ — точный порядок роста.

## Идея решения

Программа считывает массив и сортирует его по неубыванию. На каждом проходе сравниваются соседние элементы. Если левый больше правого, они меняются местами и счётчик обменов увеличивается.

После прохода максимальный элемент необработанной части оказывается справа. Поэтому на следующем проходе внутренний цикл становится на одну итерацию короче.

Флаг flag показывает, были ли обмены в текущем проходе. Если обменов не было, массив уже отсортирован и внешний цикл завершается. После сортировки выводятся массив и число обменов.

## Время сортировки в худшем случае

Для строго убывающего массива выполняются все проходы:

- первый проход: n − 1 сравнение;
- второй проход: n − 2 сравнения;
- последний проход: 1 сравнение.

Общее число сравнений:

C(n) = (n − 1) + (n − 2) + ... + 1 = n(n − 1) / 2.

Один обмен выполняется через временную переменную и требует постоянного числа операций. В строго убывающем массиве при каждом сравнении происходит обмен.

Таким образом, худшее время сортировки — Θ(n²).

## Время сортировки в лучшем случае

Если массив уже неубывающий, первый проход выполняет n − 1 сравнение и не делает обменов. Флаг остаётся false, после чего происходит break.

Лучшее время сортировки — Θ(n), а не O(1): сначала необходимо проверить весь первый проход.

## Средний случай

Для равновероятных перестановок n различных элементов среднее число инверсий равно n(n − 1) / 4. Обмен соседней пары, стоящей в неправильном порядке, уменьшает число инверсий ровно на одну. Поэтому число обменов равно исходному числу инверсий, а среднее время сортировки в этой модели — Θ(n²).

Эта средняя оценка предполагает указанное распределение входных данных.

## Время всей программы

- Создание и чтение массива: Θ(n).
- Сортировка: Θ(n) в лучшем случае, Θ(n²) в худшем.
- Вывод n элементов: Θ(n).
- Вывод числа обменов: O(1).

Лучший случай: T(n) = Θ(n) + Θ(n) + Θ(n) = Θ(n).

Худший случай: T(n) = Θ(n) + Θ(n²) + Θ(n) = Θ(n²).

## Счётчик обменов

Максимальное число обменов равно n(n − 1) / 2. При максимальном допустимом n = 99999 это 4999850001, что превышает максимальное значение int: 2147483647.

Поэтому long используется и для counter внутри bubblesort, и для возвращаемого значения метода, и для переменной в main. В данном решении все три места имеют правильный тип.

## Расчёт памяти

Исходный массив занимает O(n) памяти: 4n байт полезных данных плюс служебные расходы.

Сортировка изменяет этот же массив. Дополнительных массивов и рекурсии нет. Переменные i, j, temp, flag и counter занимают постоянный объём.

- Общая память под данные: O(n).
- Дополнительная память сортировки: O(1).

## Итог

| Случай | Время всей программы | Дополнительная память сортировки |
|---|---|---|
| Лучший: массив уже неубывающий | Θ(n) | O(1) |
| Средний: равновероятная перестановка различных элементов | Θ(n²) | O(1) |
| Худший: различные элементы в обратном порядке | Θ(n²) | O(1) |

Общая память с учётом входного массива во всех случаях — O(n).
