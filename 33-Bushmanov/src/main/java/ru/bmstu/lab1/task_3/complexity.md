# Задача 3. Подсчёт вхождений

## Обозначения и модель расчёта

`n` — количество элементов массива, `1 < n < 100000`.
Операции с `int`, сравнение, присваивание и обращение по индексу считаются операциями постоянного времени. Чтение одного числа фиксированного диапазона также учитывается как O(1). Оценивается алгоритм программы без фиксированных расходов JVM; время ожидания ввода пользователем не учитывается.

## Идея решения

Программа считывает массив и число x. Счётчик начинается с нуля. Каждый элемент сравнивается с x; при совпадении счётчик увеличивается. После просмотра всего массива выводится число совпадений.

## Временная сложность

1. Создание и инициализация массива — O(n).
2. Чтение массива — n итераций, Θ(n).
3. Чтение x и обнуление счётчика — O(1).
4. Подсчёт совпадений — ровно n сравнений. Если совпадений c, счётчик увеличивается c раз, где 0 ≤ c ≤ n. Работа цикла пропорциональна n + c, поэтому Θ(n).
5. Вывод счётчика — O(1).

Циклы чтения и подсчёта выполняются последовательно:

T(n) = O(n) + Θ(n) + O(1) + Θ(n) + O(1) = Θ(n).

Даже если все элементы совпали или не совпал ни один, нужно проверить все n элементов. Лучший, средний и худший случаи имеют порядок Θ(n).

## Пространственная сложность

Массив хранит n значений int: 4n байт полезных данных плюс служебные расходы. Общая память под данные — O(n).

Счётчик и остальные скалярные переменные требуют O(1) дополнительной памяти. Второй массив не создаётся.

Счётчик имеет тип int. Он не превышает n < 100000, поэтому переполнение счётчика при заданных ограничениях невозможно.

## Итог

- Время всей программы: O(n), точнее Θ(n).
- Общая память под данные: O(n).
- Дополнительная память подсчёта: O(1).
